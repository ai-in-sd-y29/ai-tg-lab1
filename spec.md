# Спецификация лабораторной 2

## Поведение

Сохраняются `/study`, `/translate`, `/quiz`, `/settings`, `/reset` и постоянная история lab1.
Обычный текст обрабатывается моделью с нативными function calls. Только доступные схемы
получаются через MCP tools/list, результаты проверяются по outputSchema. Чтение передаётся
модели в роли tool с источником; данные не становятся системной инструкцией.
Не более двух MCP-вызовов на сообщение, конечные тайм-ауты; модель не выполняет код.
Yandex не принимает tools и response_format одновременно: ответ без tool_calls оформляется
вторым запросом по строгой JSON-схеме TextDecision. Выбор инструментов остаётся нативным.
Служебное поле index проверяется и удаляется перед повторной отправкой сообщений.

## Контракты MCP

- `get_weather(city: str[1..100])`: status, source, различимые candidates либо current:
  город, страна, область, Celsius, weather_code, ветер с единицей, время, зона.
  Несколько совпадений означают уточнение, не выбор первого.
- `get_schedule(date: YYYY-MM-DD)`: source, date, lessons[{start,end,title,location}].
  Пустой список означает отсутствие занятий. Путь только из конфигурации.
- `add_reminder(text: str[1..500], remind_at: ISO8601 с offset)`: id, remind_at,
  timezone, created. Только будущее; доверенное подписанное разрешение передаётся
  отдельно через MCP metadata и содержит ID подготовленного действия, не параметры модели.
  Владелец и идемпотентность извлекаются из подтверждённой записи PostgreSQL.
- `schedule://current-week`: timezone, monday, sunday, days с тем же форматом занятий.
  Отдельный stdio-процесс на приложение, configured timezone по умолчанию Europe/Moscow.

Все входы запрещают лишние поля; сервер повторно проверяет аргументы.
Независимый клиент без подписанного доверенного контекста не создаёт напоминания.

## Пользовательские команды

`/tools` отображает обнаруженные инструменты и чтение/изменение; при отказе сообщает о нём.
`/timezone` показывает настройку; `/timezone Europe/Moscow` сохраняет IANA-зону и показывает
локальное время. Неизвестные зоны отклоняются. Локальное время без зоны не угадывается.
Неоднозначное/несуществующее время DST приводит к уточнению.
`/why` показывает последнее безопасное решение только своего пользователя.

## Подтверждение

Состояния: pending → confirmed → completed; pending → cancelled/expired.
Подтверждение действительно 300 секунд, привязано к владельцу и нормализованным параметрам.
Изменение действия отменяет прежнее. До согласия MCP add_reminder не вызывается.
Уникальная пара (owner, update_id) предотвращает повтор подготовки; транзакция с блокировкой
и UNIQUE(action_id) предотвращают повторное напоминание. Подтверждённая операция при сбое
допускает повтор с тем же ID, пока срок не истёк. Новые параметры требуют новой операции.

## Приёмка

Изоляция и сохранность в PostgreSQL; отсутствие дубликатов при конкурентных подтверждениях;
неизвестные инструменты, лишние поля, невалидные результаты, сетевые сбои, отсутствие города,
неоднозначные даты и инъекции не вызывают запрещённых действий или ложного успеха.
Обязательные сценарии методички покрыты тестами, конкуренция — настоящей PostgreSQL.
Неизменённый базовый набор: ≥10/12 действий и ≥8/9 аргументов. Независимый MCP-клиент
демонстрирует discovery, ресурс, чтение и отказ изменения без полномочий.
README, отчёт, результаты, тег lab2. Доставка уведомлений остаётся в lab3.
