# Демонстрация лабораторной №1

Этот файл — сценарий ручной проверки, а не утверждение, что она уже выполнена.
Нужны два Telegram-аккаунта. Не показывайте `.env`, секретные ключи и журналы личных диалогов.

## Запуск

В корне проекта, при работающем Docker Desktop:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Если PostgreSQL уже работает и зависимости установлены:

```powershell
.\.venv\Scripts\python.exe -m app
```

Если старый echo-бот работает в другом терминале или на ВМ, сначала остановите его: у одного токена должен быть один polling-процесс.

## Команды и два пользователя

1. Аккаунт A: `/start`, `/study`, «Запомни: моя учебная тема — двоичный поиск». Затем `/settings 0.0`.
2. Аккаунт B: `/start`, `/quiz`, `/settings 1.0`, «Проверь знание циклов Python».
3. Проверьте, что настройки различаются и B получил вопрос, а не объяснение темы A.
4. Аккаунт A: «Какую учебную тему я назвал?» Ответ должен учитывать предыдущий диалог. Это вероятностная проверка; сохранность записей дополнительно подтверждается тестом PostgreSQL.
5. Перезапустите только приложение через Ctrl+C и `python -m app`; volume БД не удаляйте. Повторите `/settings` и вопрос о теме A. У B продолжите ответ на вопрос опроса.
6. A: `/reset`, затем `/settings`. История очищена, температура 0.0 и режим сохранены. История B не должна измениться.
7. A: `/translate`, «Переведи на английский: Я изучаю программирование». Проверьте перевод и сообщение о сбросе истории при переключении.
8. A: `/settings 0.5`. Ожидается отказ с перечислением допустимых значений, без обращения к API.
9. Отправьте фото и текст в группе: бот не должен отвечать.

## Сбой и длинный ответ

Сначала покажите воспроизводимые автоматические проверки — они не меняют реальные настройки:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_assistant.py -k 'error_safe or long_answer' -v
.\.venv\Scripts\python.exe -m pytest tests/test_llm.py -q
```

Для живой демонстрации недоступности API в отдельном терминале задайте временное значение только для процесса:

```powershell
$env:LLM_BASE_URL='https://127.0.0.1:1/v1'
.\.venv\Scripts\python.exe -m app
Remove-Item Env:\LLM_BASE_URL
```

Перед этим остановите обычный polling-процесс. Отправьте вопрос: ожидается безопасное сообщение об ошибке. После Ctrl+C удалите временную переменную и запустите обычное приложение. `.env` менять не нужно. Не используйте запрос к случайному стороннему серверу: клиент передаёт ему API-ключ.

Для длинного ответа можно попросить модель написать текст больше 4096 символов, временно увеличив `LLM_MAX_TOKENS`, если это допускается моделью. Генерация такой длины вероятностна и расходует токены; точное разбиение, порядок, emoji и отсутствие потерь уже проверяет автоматический тест с контролируемым ответом длиннее 4096 символов.

После ручной демонстрации заполните в отчёте ФИО, группу и публичную ссылку репозитория. Сверьте результаты проверок, затем создайте локальный коммит и тег `lab1`. До ручной проверки тег не создан. Файлы `.env` и `.env.cloud` не добавляйте в Git. Публикация репозитория выполняется отдельно.
