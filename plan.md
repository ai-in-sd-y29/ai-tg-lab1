## Проверенные решения и отклонения

- Ручная проверка 17.11 выявила потерю сведений о доступных инструментах на этапе JSON-ответа.
  Добавлена передача обнаруженных MCP-контрактов в контекст этого этапа и регрессионный тест.
- Воспроизведён content_filter Yandex на выборе Воронежа после списка кандидатов.
  Уточнение в контексте сокращено, точные названия имеют приоритет над префиксами,
  отказ провайдера явно отличается от сетевого сбоя. Старые диалоги поддерживаются.
  Описание get_weather явно требует сохранить выбранную область в аргументе city.
- По просьбе пользователя погодная сводка оформлена отдельными строками со значками,
  описанием условий WMO и ветром в м/с и км/ч. Сводка из проверенных данных передаётся модели.
- Команда /tools оформлена отдельными блоками с примерами. Данные оформления передаются
  MCP-сервером в title и metadata ui и отображаются только для обнаруженных инструментов.
- Приветствие /start сгруппировано по назначению команд и дополнено примером первого сообщения.
- По просьбе пользователя вымышленная неделя повторена на 100 дней с 17.11.2026 по 24.02.2027.
  Проверены все даты, повторяемость по дням недели и отсутствие пересечений занятий.

- MCP SDK 2.3.0 вместо старых примеров FastMCP 1: использованы актуальные lowlevel handlers.
- Yandex запрещает tools и response_format в одном запросе. Нативное решение отделено от
  строгого JSON-ответа. Проверено реальным API, тест закрепляет два разных payload.
- Набор получен из официального шаблона, локально отсутствовал; сохранён без изменений с SHA-256.
- Первый прогон 11/12 и 8/9. Добавлено только правило для относительных интервалов;
  повтор исходного сбоя и полный итог 12/12 и 8/9 сохранены, несовпадение регистра не скрыто.
- Сквозной тест обнаружил UTC из PostgreSQL вместо локального времени при подтверждении.
  Исправлено явное преобразование и добавлен регрессионный тест.
- Независимый stdio-клиент, реальная погода, восемь конкурентных повторов подготовки и
  подтверждения, сохранность после перезапуска PostgreSQL проверены.
- Облачная ВМ была STOPPED и не запускалась: ручная демонстрация в Telegram остаётся
  действием на защите. Сквозной прогон использует настоящий backend с синтетическим транспортом.
